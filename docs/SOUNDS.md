# BBC Sounds (on-demand radio)

Turn on **BBC Sounds Radio** (`SOUNDS_ENABLED`, on by default) under Settings → General. It is the master switch: the other radio settings (Live Radio Stations in General, Radio Directory and Radio Media Mode on Media Management, Radio Thumbnails on Appearance) appear only while it is on, and turning it off also switches off live radio. A **Video / Radio** icon button then appears in the top bar (one tap switches; the icon shows the current mode). Radio uses the very same pages as video: Discover, Search, Categories, a category, Collections, Guide, Channels and the programme page (one page for both), with the same filters, sorting, pagination and cards, fed from BBC Sounds instead of iPlayer. The choice is remembered per browser. With it off, the switch, the radio data, the API and the daily job do not exist.

The switch keeps you on the page you are on when the page exists in both modes (Discover, Search with its term, Categories, Collections, Guide, Channels, Queue and so on). A page that shows something only one catalogue has cannot follow: a programme opens a search for its title, a category goes to the Categories list, and A to Z (which BBC Sounds lacks; it stays in the menu, greyed out) goes to Categories.

## What it does
- **Search** BBC Sounds for programmes and episodes (results table or posters, with the series and an estimated size). BBC's search is loose, so Settings → Search has a **Radio Search** block (it appears while Sounds is on): Match All Search Words, Best Title Matches First and, under Advanced, shows/episodes/both, MP3 episodes only, a network list and a result cap (see [CONFIG.md](CONFIG.md)). The Native Search settings are for iPlayer only; the Search page notes the radio setup below its results. The top bar's type-ahead suggests radio shows in radio mode. **Discover** shows its featured rails, **Categories** lists its categories with a picture each (a category page lists its sub-categories as buttons), and **Collections** its curated sets with episode counts. **Channels** and **Guide** list the live radio stations (needs Live Radio Stations on) in radio mode and the TV channels in video mode.
- Click a programme to open its page, which is the video programme page: banner, **Subscribe**, **Download all**, series tabs (Sounds has no series list, so a series is read from the episode titles; shows with none get one list), and its episodes (newest first, sortable, paged) with Play, Download and, with Show Extended Debug, a debug button (it reads the highlighted episode, else the first listed).
- **Play** any episode in the browser. It plays BBC's own clear audio stream through iPlayarr (the Stream Key must be set). The player stays at the bottom while you browse.
- **Download** an episode into the **Radio Directory** (`SOUNDS_DIR`, required). The choice of what to save is made per download (a dialog, like video) and starts from **Radio Media Mode** (`RADIO_MEDIA_MODE`):
  - **Audio file** (`m4a`, the default): `Show/Show - 2026-11-06 - title.mp3` (or `.m4a`) with tags (artist, album, title, date, description), embedded cover art, and a `cover.jpg` in the show folder. Point a Jellyfin **music** library at that folder. Where Sounds offers a plain MP3, that file is fetched as is (no re-encoding); otherwise (most music shows) the episode is recorded from its stream, audio copied, to `.m4a`.
  - **`.strm` link** (`strm`): a tiny `Show/Show - 2026-11-06 - title.strm` that plays the audio stream through iPlayarr (`/api?mode=stream&audio=1&pid=...&streamkey=...`), plus the show's `cover.jpg`. It takes no disk space, needs the Stream Base URL and Stream Key, and its key is rewritten when the Stream Key is rotated. Jellyfin's music libraries may not play `.strm` files (untested); a mixed or video library may be needed.
  - Subscribed programmes use the Radio Media Mode setting.
- Recording is fast: the stream's segments are fetched six at a time into one file, which is then copied into the tagged file. Radio streams are small (about 6 to 17 kB/s of audio; BBC's worldwide pool serves 48 kbps HE-AAC), so the kB/s figure on the Queue is naturally far lower than for video. It is timed from the first segment, so setup does not drag it down.
- Radio downloads appear on the **Queue** page beside video ones, marked Radio, with size, speed (in kB/s) and ETA. Cancel and remove work from there, and a failed download has a **Try again** button. At most **Radio Download Limit** (`RADIO_ACTIVE_LIMIT`, default 2, Settings → Download Client → advanced) run at once, apart from the video limit. They are never shown to Sonarr or Radarr. The Queue page reads them from the same queue API as video, with `?mode=radio` (`/json-api/queue/queue`, `/history`, and `POST /history/retry`).
- **Subscribe** to a programme and choose, as for video: only new episodes from now on, new episodes and the latest one now, or new episodes and the newest available ones now (up to 100). A job (hourly, listed under Maintenance as Radio Subscriptions) queues each new episode, saved the way Radio Media Mode says. Radio subscriptions are listed on **Subscriptions** with how many episodes were queued, the last download, when each was last checked, and **Check all now**. There is no Sonarr/Radarr link or version choice for radio.
- Two downloads run at a time; finished files stay on disk when the list entry is removed.
- **Streaming debug** (Show Extended Debug) works for a radio episode: it asks BBC's mediaselector for the audio and reads the playlists for bitrate and codec, with the picture, details and a player, and none of the video-only parts. The probe runs by itself when the page opens.
- **Radio Thumbnails** (`RADIO_THUMBNAIL_STYLE`): radio artwork is square, so it is shown whole in the wide picture boxes, over a blurred copy of itself (`blur`, the default) or on a plain dark box (`square`). The same everywhere (cards, the programme page and its episodes), except the Discover banner, which always keeps the blurred backdrop.

## Notes
- It uses BBC Sounds' public catalogue API, not a login, so it is unofficial and BBC can change it. For personal use only; keep it polite (no bulk mirroring).
- Streams come from BBC's worldwide audio pool, so downloads and playback do not need a UK IP in testing, but BBC can restrict some content.
- Episodes expire; a subscribed programme only downloads what is available when the job runs.
- Video features never see radio: a radio `.strm` carries `audio=1` and a Sounds id, which is not an iPlayer pid, so subscription detection and the video library index ignore it. Radio has its own parts instead. The **library index** keeps separate radio scans of the Radio Directory and of each Jellyfin music library. A file is identified by its `.strm` link, by the episode id new downloads write into the audio tags (`iplayarr_id`), or failing that by the `<Show> - <date> - ...` name. Radio then works like video from it: the Subscriptions card shows on disk over episodes seen with per-source icons, a show's page marks the episodes on disk (`GET /json-api/browse/programme/:id/on-disk?mode=radio`), the missing-episodes list shows a followed show's episodes not on disk (its older `/json-api/sounds/follows/:id/missing` route is switched off), and the library debug page has a Video / Radio filter. The **STRM Watchdog** checks radio `.strm` links against BBC Sounds when `radio` is a Watchdog Source (see [WATCHDOG.md](WATCHDOG.md)).
- Radio always uses the built-in downloader and streamer. The Download Client and Stream Client settings are for video (get_iplayer and yt-dlp cannot fetch BBC Sounds), so there are no separate radio ones.
- Radio downloads are a separate queue from video's (their own list and Queue rows), but they write to the same **Events** log, flagged Radio, and the Queue, Subscriptions, Events, Statistics, Streaming and Watchdog pages always show radio and video together. Only the browse pages (Discover, Search, Categories, Collections, Channels, Guide and a programme) follow the Video | Radio switch.
- Radio listings and searches are cached in the database (**Radio Listings**, **Radio Search** on Maintenance and Statistics) and radio pictures go through the thumbnail cache, so both survive a restart.
- A category or collection lists at most its newest 300 episodes, not programmes (BBC's own programme list for a category is mostly TV).
- Live radio stations are separate: see [STREAMING.md](STREAMING.md#live-radio).
- **Download collection** works for a radio collection as for a video one: the button shows how many episodes it would queue (those not already queued or downloaded, at most the first 100), asks how to save them (audio file or `.strm` link), queues them in the collection's order and takes you to the Queue.
- A radio download (one episode, **Download all**, or ticked rows in Search) asks once how to save it, queues the episodes and takes you to the Queue, as video does. Episodes the server refuses are reported together in one message.
- Playing a radio episode (in the browser or from a `.strm` link) counts as a stream session on the Streaming page, named after the show and episode, and its segments are counted like any other. Radio always streams as direct HLS audio whatever Stream Mode says. The player bar stops when a video starts (and the reverse), when BBC Sounds is turned off, and on sign-out.
- A download, subscription or debug view asks for an episode by id, and the server only accepts one it listed in the last 12 hours (BBC has no single-episode lookup to fall back on). A page left open longer, or across a restart, says the episode is no longer in the list: open the show or search again.
- Radio station schedules are cached in the database (**Radio Schedules** on Maintenance, 8 hours) and refreshed by the same daily job as the TV guide. A BBC rate limit or blip is retried a few times.
- A block in the radio Guide opens the show's radio page with that episode picked (a live slot with no episode yet opens the show). A schedule cached before this was added opens a search for the title until it refreshes; clear **Radio Schedules** to get the links at once.
- The Radio Directory must be a full path (it is created on first use); the settings page rejects a relative one.
- BBC Local Radio stations are not offered: only the 16 national stations (see Live radio in [STREAMING.md](STREAMING.md#live-radio)).

### API

Radio is the same API as video with `?mode=radio` on `/json-api/browse`, `/json-api/search` and `/search/stream`, `/json-api/queue`, `/json-api/subscriptions` and `/json-api/library`; routes that change something or look up iPlayer (`/browse/details`, `/versions`, `/markers`, a category's Discover) answer 404 for radio. `POST /browse/collections/:id/download?mode=radio` queues a collection's episodes (`{ dryRun: true }` only counts them, `{ mode: "m4a" | "strm" }` says how to save them). The older `/json-api/sounds/...` paths for browse, search, shows, on-disk, the download list and follows are switched off (commented out in `SoundsRoute.ts`, to delete in a code review); only `POST /json-api/sounds/downloads` and `GET /json-api/sounds/status` remain. `?mode=radio` answers 404 while BBC Sounds is off.
